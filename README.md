# TG Recovery

Веб-панель для приёма кодов авторизации Telegram. Держит постоянные Telethon-сессии
для добавленных аккаунтов, ловит сообщения от служебного аккаунта Telegram (777000),
достаёт из них код и показывает в интерфейсе.

- FastAPI + Jinja2, SQLite, Telethon
- Вход по паролю (Argon2) + опциональная TOTP-двухфакторка
- Несколько пользователей: у каждого свой вход и свои Telegram-аккаунты
- Файлы сессий и облачные пароли шифруются (Fernet)
- Журнал действий, автоочистка старых кодов, резервные копии

> Работает только с аккаунтами, к которым у вас есть законный доступ.
> Файлы сессий равносильны входу в Telegram — храните их как пароли.

## Быстрый старт локально

Требуется Python 3.10 или новее.

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# заполните TG_API_ID, TG_API_HASH (my.telegram.org)
# и два ключа:  openssl rand -hex 32
$EDITOR .env

python -m scripts.init_admin          # создать администратора
uvicorn app.main:app --reload         # http://127.0.0.1:8000
```

Тесты:

```bash
pip install -r requirements-dev.txt
pytest
```

## Установка на VPS (Ubuntu + nginx + Let's Encrypt)

`install.sh` ставит зависимости, создаёт systemd-сервис, настраивает nginx,
получает сертификат и прописывает ежедневный бэкап в cron. Секретов в скрипте нет —
он спросит их при запуске (или возьмёт из окружения):

```bash
sudo TG_API_ID=... TG_API_HASH=... DOMAIN=example.com \
     LE_EMAIL=you@example.com ADMIN_PASS='...' bash install.sh
```

Повторный запуск — это обновление: код обновится, база, сессии и ключи шифрования
сохранятся. Остановить проект без удаления данных — `sudo bash uninstall.sh`.

### Если сертификат не выдаётся и сайт остаётся на http

Установщик перед запросом сертификата проверяет DNS и печатает вывод certbot
в `/var/log/tg_recovery_certbot.log`. Частые причины:

1. **A-запись есть только для `www`.** Сертификат запрашивается и для корня домена,
   поэтому нужна запись `Type=A, Name=@` с IP сервера, а не только `Name=www`.
   Проверить: `getent hosts example.com` — должен вернуть IP сервера.
2. **Cloudflare в проксирующем режиме** (оранжевое облако). Для HTTP-01 нужен
   режим **DNS only** (серое облако); после выпуска сертификата проксирование
   можно включить обратно.
3. **80-й порт закрыт.** `sudo ufw allow 'Nginx Full'`.
4. **Исчерпан лимит Let's Encrypt** — 5 неудачных проверок в час на домен.
   В логе будет `too many failed authorizations`; нужно просто подождать час.

Перевыпустить сертификат отдельно, не запуская установщик целиком:

```bash
sudo certbot --nginx -d example.com -d www.example.com \
     --non-interactive --agree-tos --redirect -m you@example.com
```

## Развёртывание на Railway

Приложение держит постоянное соединение с Telegram, поэтому сервис должен работать
круглосуточно, а данные — переживать передеплой. Обязательны два условия:
**том (Volume)** и **выключенный App Sleeping**.

1. **New Project → Deploy from GitHub repo** → выберите этот репозиторий.
   Nixpacks сам увидит `requirements.txt`; команда запуска берётся из `railway.json`.

2. **Volume.** Service → Settings → Volumes → New Volume, mount path `/data`.
   Без тома файловая система контейнера обнуляется при каждом деплое, и все
   добавленные Telegram-аккаунты пропадут.

3. **Variables** (Service → Variables):

   | Переменная | Значение |
   |---|---|
   | `TG_API_ID` | из my.telegram.org |
   | `TG_API_HASH` | из my.telegram.org |
   | `SECRET_KEY` | `openssl rand -hex 32` |
   | `ENCRYPTION_KEY` | `openssl rand -hex 32` (другой!) |
   | `ENV` | `production` |
   | `HOST` | `0.0.0.0` |
   | `DATABASE_PATH` | `/data/recovery.db` |
   | `SESSIONS_DIR` | `/data/sessions` |
   | `TRUSTED_PROXY_HOPS` | `1` |
   | `SEND_SECURITY_HEADERS` | `1` |

   `PORT` Railway подставляет сам — задавать не нужно.

4. **Settings → Networking → Generate Domain** — получите адрес `*.up.railway.app`.
   HTTPS Railway даёт сразу, поэтому `ENV=production` (Secure-cookie) корректен.

5. **Settings → выключите Serverless / App Sleeping.** Спящий сервис не держит
   соединение с Telegram и коды приходить перестанут.

6. **Создайте администратора.** Через Railway CLI:

   ```bash
   railway run python -m scripts.init_admin
   ```

   Либо разово задайте переменные `TGR_ADMIN_USER` и `TGR_ADMIN_PASS` и добавьте
   `python -m scripts.init_admin &&` в начало start command — при следующем старте
   администратор создастся сам (скрипт ничего не делает, если такой логин уже есть).
   После этого переменные и приставку можно убрать.

Бэкапы на Railway делает сама фоновая задача приложения (cron там нет) — файлы
складываются в `/data/backups`. Скачать их можно только изнутри контейнера
(`railway ssh`), поэтому важные копии выгружайте наружу вручную.

### Сколько это стоит

Бесплатного тарифа «навсегда» у Railway нет. Новый аккаунт получает Trial —
разовые **$5 на 30 дней** без карты; когда кончится любое из двух, контейнер
останавливается, а данные тома хранятся ещё 30 дней. Дальше — Hobby $5/мес,
куда входит $5 потребления.

Этому приложению нужно ~0.2 ГБ RAM и почти нулевой CPU, то есть примерно
**$2–3 в месяц** плюс том ($0.15 за ГБ). В Hobby укладывается, в Trial хватит
на месяц. Тариф Free с $1 кредитов в месяц для круглосуточного сервиса мало.

Ограничение архитектуры: **только один экземпляр** (`numReplicas: 1`). Telethon-клиенты
и незавершённые добавления живут в памяти процесса, а SQLite — в одном томе;
второй реплики этот код не переживёт.

## Пользователи и доступ

Первого администратора создаёт `scripts/init_admin.py`. Дальше учётные записи
заводятся из интерфейса: **Настройки → Пользователи** (раздел виден только
администраторам).

- Каждый пользователь видит **только свои** Telegram-аккаунты, коды и журнал.
  Чужие недоступны даже по прямой ссылке.
- Обычный пользователь управляет своими аккаунтами, паролем, логином и 2FA.
- Администратор дополнительно: заводит и удаляет пользователей, задаёт им
  пароли, выдаёт и снимает права, управляет резервным копированием.
- Бэкап забирает базу и сессии **всех** пользователей, поэтому доступен
  только администраторам.
- Последнего администратора нельзя разжаловать или удалить, себя удалить тоже
  нельзя — иначе панель осталась бы без управления.
- Удаление пользователя отключает и стирает все его Telegram-аккаунты.
- Смена пароля (своя или заданная администратором) завершает все сессии
  этого пользователя на других устройствах.

## Резервные копии

Настройки → Резервное копирование (только администратор):

- **Расписание** — автоматические копии раз в день, неделю или месяц.
  Хранятся в `data/backups`, старше `BACKUP_RETENTION_DAYS` удаляются.
- **Готовые копии** — список архивов с кнопкой «Скачать». Держите копию вне
  сервера: в архиве база и зашифрованные сессии, то есть доступ к аккаунтам.
- **Восстановление** — загрузка архива обратно. Приложение проверяет, что это
  наш бэкап и что база цела, отключает Telegram-клиентов, подменяет данные и
  просит войти заново. Прежние база и сессии остаются рядом с пометкой
  `.replaced-<дата>` — если что-то пойдёт не так, их можно вернуть руками.

Архив расшифровывается тем `ENCRYPTION_KEY`, с которым его создали. Переносите
бэкап на другой сервер только вместе с ключом из `.env`, иначе сессии
восстановятся, но не откроются.

## Сессии

Cookie сессии — **сеансовая**: закрыли браузер — вышли из панели. Дополнительно
действуют два срока: `SESSION_IDLE_TIMEOUT` (простой без действий, окно
скользящее) и `SESSION_MAX_AGE` (предел от момента входа). Таймаут простоя
нужен в том числе потому, что браузеры с восстановлением вкладок умеют
возвращать сеансовые cookie после перезапуска.

## Переменные окружения

Полный список с пояснениями — в [`.env.example`](.env.example). Самое важное:

- `ENCRYPTION_KEY` — им зашифрованы файлы сессий и облачные пароли.
  **Смена ключа делает уже сохранённые сессии нечитаемыми**, аккаунты придётся добавлять заново.
- `SECRET_KEY` — подпись cookie. Смена просто разлогинивает всех.
- `TRUSTED_PROXY_HOPS` — сколько прокси стоит перед приложением. Значение больше
  реального позволяет подделать IP в заголовке и обойти лимит попыток входа;
  если приложение доступно из интернета напрямую, ставьте `0`.

## Структура

```
app/
  main.py               точка входа, фоновая задача, обработчики ошибок
  config.py             конфигурация из окружения
  database.py           схема, миграции, доступ к SQLite
  auth.py               сессии, лимит попыток, определение IP
  crypto.py             Argon2, Fernet, TOTP
  telegram_manager.py   Telethon-клиенты, добавление аккаунтов
  backup_service.py     резервные копии
  routes/               HTTP-маршруты
scripts/
  init_admin.py         создание администратора
  backup.py             бэкап для cron
tests/                  pytest
```
